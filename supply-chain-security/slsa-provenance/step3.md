# Understand SLSA levels and what Chains provides

SLSA defines four levels of increasing security guarantees. In this step, we
will understand each level and demonstrate that Tekton Chains provides L1 and
L2 guarantees out of the box.

## SLSA levels overview

| Level | Requirement | What it means |
|-------|-------------|---------------|
| **L1** | Provenance exists | A record of how the artifact was built exists |
| **L2** | Signed provenance | The provenance is signed by the build platform |
| **L3** | Hardened build | The build platform is tamper-resistant |
| **L4** | Two-person review | All changes require code review |

## L1: Provenance exists

We already achieved this in Steps 1 and 2. Chains automatically generated
SLSA provenance for our TaskRun:

```bash
TASKRUN_NAME=$(kubectl get taskrun --sort-by=.metadata.creationTimestamp -o jsonpath='{.items[-1].metadata.name}')
echo "TaskRun: $TASKRUN_NAME"
echo ""
echo "Provenance annotation present:"
kubectl get taskrun "$TASKRUN_NAME" \
  -o jsonpath="{.metadata.annotations}" 2>/dev/null \
  | python3 -c "import sys,json; d=json.load(sys.stdin); print('  payload:', 'YES' if any('payload' in k for k in d) else 'NO'); print('  signature:', 'YES' if any('signature' in k for k in d) else 'NO')"
```

The provenance exists (L1 satisfied) and is automatically generated by Chains
with no manual intervention required.

## L2: Signed provenance

L2 requires that the provenance is **cryptographically signed** by the build
platform. This prevents tampering -- an attacker cannot modify the provenance
without invalidating the signature.

### Extract the signature

```bash
kubectl get taskrun "$TASKRUN_NAME" \
  -o jsonpath="{.metadata.annotations.chains\.tekton\.dev/signature-taskrun-$TASKRUN_NAME}" \
  | base64 -d > /tmp/signature.raw
echo "Signature extracted ($(wc -c < /tmp/signature.raw) bytes)"
```

### Extract the payload

```bash
kubectl get taskrun "$TASKRUN_NAME" \
  -o jsonpath="{.metadata.annotations.chains\.tekton\.dev/payload-taskrun-$TASKRUN_NAME}" \
  | base64 -d > /tmp/payload.raw
echo "Payload extracted ($(wc -c < /tmp/payload.raw) bytes)"
```

### Verify the signature with cosign

Use cosign to verify that the signature matches the payload using the public
key we generated in Step 1:

```bash
cosign verify-blob \
  --key cosign.pub \
  --signature /tmp/signature.raw \
  --insecure-ignore-tlog \
  /tmp/payload.raw
```

If you see `Verified OK`, this confirms:

1. The provenance was signed with the private key that matches `cosign.pub`
2. The provenance payload has not been tampered with since signing
3. **SLSA L2 is satisfied** -- the provenance is authenticated

The `--insecure-ignore-tlog` flag is used because we are in a local
environment without access to the Rekor transparency log. In production, you
would use a transparency log for additional guarantees.

## L3 and L4: Beyond Chains alone

**L3 (Hardened build)** requires that the build platform itself is
tamper-resistant. This means:
- Build steps cannot influence each other's provenance
- The provenance cannot be falsified by the build process itself
- The build environment is isolated

Tekton provides some L3 properties because each Step runs in a separate
container and Chains observes the TaskRun externally. However, full L3
typically requires additional infrastructure hardening.

**L4 (Two-person review)** is a policy requirement that all source changes are
reviewed by at least two people. This is outside the scope of the build system
and is enforced by your source control platform (e.g., GitHub branch
protection rules).

## Verify the full chain of trust

Let's do one final end-to-end verification to confirm everything works
together:

```bash
echo "========================================"
echo "  SLSA PROVENANCE VERIFICATION REPORT"
echo "========================================"
echo ""
echo "TaskRun: $TASKRUN_NAME"
echo ""

# Check L1: provenance exists
PAYLOAD=$(kubectl get taskrun "$TASKRUN_NAME" \
  -o jsonpath="{.metadata.annotations.chains\.tekton\.dev/payload-taskrun-$TASKRUN_NAME}" 2>/dev/null)
if [ -n "$PAYLOAD" ]; then
  echo "L1 (Provenance exists): PASS"
else
  echo "L1 (Provenance exists): FAIL"
fi

# Check L2: signed provenance
SIGNED=$(kubectl get taskrun "$TASKRUN_NAME" \
  -o jsonpath='{.metadata.annotations.chains\.tekton\.dev/signed}' 2>/dev/null)
if [ "$SIGNED" = "true" ]; then
  echo "L2 (Signed provenance):  PASS"
else
  echo "L2 (Signed provenance):  FAIL"
fi

# Verify with cosign
echo ""
echo "Cosign verification:"
cosign verify-blob \
  --key cosign.pub \
  --signature /tmp/signature.raw \
  --insecure-ignore-tlog \
  /tmp/payload.raw 2>&1

echo ""
echo "L3 (Hardened build):     PARTIAL (Tekton provides container isolation)"
echo "L4 (Two-person review):  N/A (source control policy)"
echo ""
echo "========================================"
```

## What Chains gives you out of the box

To summarize what Tekton Chains provides automatically:

- **L1** -- Provenance is generated for every TaskRun without any manual steps
- **L2** -- Provenance is signed with a cryptographic key managed by the
  cluster administrator
- **Partial L3** -- Tekton's container-per-Step architecture provides some
  isolation guarantees

For production deployments, you would additionally:
- Store keys in a KMS (HashiCorp Vault, AWS KMS, GCP KMS)
- Enable transparency logging with Rekor
- Use admission controllers to enforce signature verification before deployment
